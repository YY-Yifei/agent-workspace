# Agent Workspace · 完整认识

> 这份文档是项目的锚。细节在 `desktop-workspace-plan.md` 与 `plugin-mechanism.md`；
> 这里只回答三件事：它是什么、为什么是开创性的、该怎么造。

---

## 一、一句话

**一个会长的软件。**

出厂时它几乎什么都不会，只有一个小助理；用户跟它说话，它替用户写程序；
程序留在工作区里，人点着用，agent 也能调同样的东西。

它的产能不是版本号，是用户自己攒出来的 `plugins/`。

---

## 二、换位：agent 是程序员，不是助手

| | 助手 | 程序员 |
|---|---|---|
| 产物 | 一次回答 | 一件留下的东西 |
| 生命周期 | 说完就没了 | 造完一直在 |
| 用户关系 | 询问 | 委托 |
| 系统进化 | 等厂商发版 | 每次交付都长一寸 |

这个换位定住了整个产品。所有设计取舍都从它推出：

- 产物是**程序**，程序要有状态、有入口、能独立跑；
- 所以界面不是「聊天记录」，是**程序集合 + 对话**；
- 所以「人能用、agent 也能用」不是附加功能，是**同一件事的两面**。

**北极星指标不是消息数，是每个用户每周新增/使用的插件数。**
聊天很热闹但一个插件都没长出来的工作区，是失败的。

---

## 三、开创性的位置在哪

传统软件的**功能集在发布时确定**。
这里的**功能集在使用中生长**，上限由用户自己的需求决定。

由此产生一个以前不存在的设计对象：

> **你写的「API 文档」，读者是 AI。它读完，就能改写你的软件。**

传统软件设计两样东西：给人用的界面、给人写的文档。
这里要设计三样，且第二样最重要：

1. **给人用的界面** —— 程序要好看好点；
2. **给 agent 读的说明书** —— `instructions` + 插件契约；这是软件的「扩展接口」；
3. **两者的同一性** —— 同一份能力定义，长出两个入口（模型可调 / 界面可点），一条执行路径。

第 3 条是技术骨架，第 2 条是产品灵魂。做不好第 2 条，agent 造出的插件就是一堆 demo。

---

## 四、谱系：道 · 一 · 二 · 三 · 万物

**道 = Agent。一 = 内核。**

- **道 —— Agent。** aaas-service 里那份模型与 ReAct 循环。**唯一的智能来源。**
  它不在我们的进程里，也不该在。它无形状、可替换、天生会思考。
- **一 —— 内核。** 把道落到这台机器上的那**一个**东西：一个目录约定、一条 dispatch、
  一条事件流、一次 declare。它的功能面是封闭的、可枚举的、**不含一克智能**。
- **二 —— 双入口。** 同一份能力，人和 agent 各一扇门，走同一条执行路径。
- **三 —— 插件三要素。** 能力（backend）/ 页面（ui）/ 状态（data）。
- **万物 —— 工作区。** 用户和 agent 一起攒出来的、能日用的程序集合。

道生一，一生二，二生三，三生万物。这条链是本项目的结构本身，不是比喻。

**上一版我把 三 记在了 ReAct 循环头上，那是错的。** 判据很简单：
**三 必须能生万物。** 循环生产的是回答，一次性的；只有插件生产「留下的东西」。
循环在道里，不在三里。

```
道  Agent（模型 + 循环）        ← 会在外面，可以换
└ 一 内核（四件事，无智能）      ← 我们的全部代码
  └ 二 双入口（人 / agent）      ← 少了它，链条断在一，长不出万物
    └ 三 插件（能力 / 页面 / 状态）
      └ 万物 工作区（用户攒出来的软件）
```

---

## 五、从谱系推出的六条

**1. 内核不许聪明。** 道是一，内核若思考，就成了第二个道。
任何「如果模型调了 A，那么接下来做 B」的本地逻辑，都是把智能从道里偷回来。
我们每替模型做一次决定，就替它压低一次天花板。

**2. 内核必须是单数。** 「一」不可分：唯一 dispatch、唯一事件流、唯一目录约定。
出现第二条执行路径，道就没有身体了 —— 这是「唯一执行入口」红线真正的理由。

**3. 道可换，万物不动。** `config.json` 里的 aaas 地址就是道的入口。
换一个 service、换一个模型，同一个工作区照旧打开，插件全在、数据全在。
**你的工作区不是某个模型的附属物，它的价值在万物，不在道。** 这条是产品级的资产论。

**4. 内核只做四个动作：** 落盘、传话、执行被点名的、广播。
四个动词之外的一切，都属于道或属于万物。

**5. `instructions` 不是内核的智能，是内核替道携带的自述。**
协议规定它 MUST 不进历史、每轮临时注入 —— 于是「改提示词即改它的自我认知」，
且不污染历史。这是内核替道做的最贴身的服务。

**6. 「二」是产品成立的条件。** 只有一（只有 agent 能调的能力面），停在工具；
有了二（人也能点），才有三和万物。所以自动能力面板不是兜底 UI，是**谱系的第二个字**。

---

## 六、极简的边界：不做什么

不写：第二个 agent、本地编排、插件沙箱、前端框架与构建链、组件库、状态管理库、
数据库、主题、设置页、插件市场。

判据两条：

- **道能给的、浏览器能给的，我们都不写。**
- **内核多一行代码，道就少一寸地方。**

---

## 七、产品的心跳：「固化」

每次对话有两种结局，产品必须把用户引向后一种：

| | 一次性 | 可复用 |
|---|---|---|
| 例子 | 「帮我总结这个文件」 | 「我每周都要交周报」 |
| 结局 | 沉入历史 | **固化成插件** |

**判断谁做：agent 提议，用户确认。** 这个产品最好的一句台词是：

> 「这周你让我做了四次类似的整理，要不要我把它做成一个按钮？」

这一句把聊天工具变成软件工厂。没有它，用户永远在对话里干活、工作区永远是空的 ——
于是道再强，万物为零。

---

## 八、agent native 的定义

不是「有 AI 功能」，是三条同时成立：

1. **人不需要 agent 也能用** —— 能力面板 / 自定义页 / 命令面板；
2. **agent 用完全相同的 entry point**，没有特权通道；
3. **双方看得见对方的动作** —— `source` 随事件广播。

最直观的一瞬：用户在对话里说「开始一个番茄钟」，**旁边页面的数字自己动起来**。
人和 agent 在同一个房间，不是两个房间各说各话。

---

## 九、怎么造：按「能证伪」排序

**不要先做漂亮的聊天框。** 做得再好也只是又一个 chatbot；
如果 agent 造不出好插件，叙事就崩了。**先证明产物，再美化过程。**

- **M0**（1.5d）一条真链路，命令行可见：`connect → declareAgent → sendInput →
  functionCall.ready → 本地执行 → functionResult → turn.completed`
- **M1**（2d）**一件真产物**：真插件 + 自动能力面板 + 页面。此时就该给陌生人看
- **M2**（1.5d）双向可见：对话里的动作让页面数字变化
- **M3**（2d）**演化闭环**：说一句话 → 多一个能点的程序。产品成立
- **M4**（3d）可日用：历史折叠、图片、断连重连、多工作区
- **M5** 持续：把插件质量当产品指标

**M3 之前不做**：CSS 框架、主题、设置页、市场、多语言。

---

## 十、红线与风险

**三条红线**

1. **唯一执行入口** —— 人 / agent / 插件全走 `dispatch`。破一次，两条路径永久漂移。
2. **单一真相** —— 一个约束只写一处（`Annotated`）→ schema / 表单 / 校验同源。
3. **磁盘即状态** —— 内存随时可丢；代码目录与数据目录分离（改代码不动用户数据）。

**四个风险，三个不是技术问题**

| 风险 | 症状 | 对策 |
|---|---|---|
| **产物质量** | 插件像 demo 不像程序 | 「程序感清单」写进 instructions：持久状态 / 独立入口 / 键盘可达 / 能撤销 / 有历史 |
| **同质化** | 所有插件都是「表单+列表」 | 3 个形态迥异的示例插件（计时器 / 看板 / 图表）当风格锚 |
| **一次性化** | 永远在对话里干活，从不固化 | agent 主动提议固化 |
| **空板子** | 连不上 aaas 就什么都没有 | 如实报错 + 配置向导；**不做假聊天降级** |

## 十一、验收

给一个陌生人、10 分钟、不讲解：他讲一句话 → 侧边多出一个卡片 → 他自己点着用了三次。

做到，产品成立。只做到「聊得挺好」，就是又一个 chatbot。

## 十二、接力轮：唯一一处「本地开轮」，以及它为什么还不是编排

M3 落地时新增的一段代码（`link.py::_open_turn`）。它值得单独写一节，因为它是整个
系统里**唯一**看起来像「本地决定下一步」的地方 —— 而它其实不是。

### 它是什么

```python
final = await self._one_turn(text)
while self._new_caps() and self._continues < 3:      # 本轮内长出过新能力
    await self._declare()                            # 让新能力进入声明
    final = await self._one_turn(handoff_text)       # 再开一轮，把控制权交回道
```

### 为什么必须有

协议规定：**声明只影响后续轮次**（轮即栅栏）。于是模型在轮内造出插件的那一刻，
它对模型自己是**不可见**的 —— 不接力，模型这辈子都用不上自己刚写的东西，
「说一句话就多一个能点的程序」这句话就是假的。

### 为什么它不违反「本地不写下一步逻辑」

判据只有一条：**它有没有替模型做决定？**

- 不判断该不该做、不判断做得好不好、不选择工具、不改写模型输出；
- 触发条件是**结构性的**：`本轮能力面 ≠ 轮初能力面`。这不是策略，是可测的事实；
- 交班语只陈述事实（「新增了这些能力，现在可用」），不指定动作；
- 上限 3 轮，防的是死循环，不是防模型做错事。

一句话：**它不决定做什么，它只把「轮边界到了」这件事告诉道。** 这是协议要求的
礼貌，不是编排。

### 踩过的坑（留给下一个实现者）

1. **判据不能用版本号。** 内核有一个后台循环每 0.5 秒检查版本变化就重新声明 ——
   它会把版本「追平」，于是 `rt.version != _declared_version` 永远为假，接力永不触发。
   正确判据是**能力面本身的差异**（轮初快照 vs 现在）。
2. **话术要写成禁令。** 最初写「下一轮开始可用」，模型读成「也许可以试试」，
   当场连试 3 次 `ToolNotFoundError`，白烧一轮。改成「本轮不要调用这些能力」才拦住。
