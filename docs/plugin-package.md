# 插件包 `.awp` —— 把一个程序搬走，再搬回来

一句话：**导出 = 把这个程序装进一个文件；导入 = 把那个文件装成 `plugins/<pid>`。**
两块都在设置面板（⚙）里，靠在一起：上面「导出插件」，下面「导入插件」。

它解决的问题只有一个：程序是**用户攒出来的**，攒在 `workspace/plugins/<pid>/` 里。
换台机器、给同事看一眼、重装之前留一份 —— 这三件事都不该靠「拷一个目录」，因为
没人记得住「哪些文件算程序、哪些不算」（`.git/`、`__pycache__/`、`data/` 都在同一个目录里）。

---

## 1. 包里有什么

一枚 `.awp` 就是一枚 zip，根上只有两样东西：

```
awp.json                包的身份：格式号 / pid / 标题 / 导出时间 / 带没带数据 / 文件数
plugin/plugin.json      程序本体（和 plugins/<pid>/ 里那几个文件一样）
plugin/backend.py
plugin/ui/**
plugin/data/**          只有勾了「连同数据」才有
```

**为什么程序本体住在 `plugin/` 底下，而不是摊在 zip 根上**：摊开以后「包的身份」与
「插件的内容」混在同一层，一个恰好叫 `awp.json` 的插件文件就跟包身份撞名了。
现在判据只有一条：**条目要么是 `awp.json`，要么在 `plugin/` 底下，别的都不该存在。**

**哪些文件算程序**：复用版本化那份白名单（`pluginvcs.tracked()`）——
`plugin.json` / `backend.py` / `ui/**`，减去 `.git` / `__pycache__` / `*.pyc`。
不另写一份清单：两份判据必然走岔，而走岔的表现是「历史里有、包里没有」那种没人查得出来的差别。

---

## 2. 「数据」到底指什么（这一条最容易想当然）

| 东西 | 位置 | 进包吗 |
|---|---|---|
| 程序自己攒的 | `plugins/<pid>/data/**`（`ctx.get/set` 的 `store.json` 也在里面） | **可选**，默认不进 |
| 对话 | `workspace/sessions/<pid>/` | **不进** |

第一行是「数据」，第二行不是：对话是**宿主的会话库**，与插件目录同级，跟着「你在哪台机器
上用过它」走，不跟着程序代码走。所以「导出这个程序」= 导出这个程序，不是导出一段历史。
（如果哪天要「把这台机器上的对话一起搬走」，那是另一个包、另一份判据 —— 不是这一个。）

---

## 3. 默认不导出：三层各判一次，而不是界面上一枚默认值

1. **签名**：`pluginpkg.build(pdir, include_data=False)` —— 默认参数就是「不带」。
2. **服务端**：`GET /api/plugins/export?pid=…` 不带 `data=1` 就不打包 `data/`。
3. **界面**：那枚勾选框每次打开面板都**归零**（`$('#expdata').checked = false;`）。

为什么三层：**记住上次的选择等于默认导出** —— 人记住的是「上次导过一次」，而
「这次带没带数据」不会有人再去看第二眼。所以这里不做「记住偏好」，只表达这一次的选择。
判据落在服务端，是因为界面是可以被忘记重置的，而数据不是可以被悄悄带走的东西。

---

## 4. 导出：先看一眼，再给文件

点「导出」之前，面板已经报过一次数（`dry=1`）：

```
会装进 12 个文件 / 8 KB（其中数据 3 个）· pomodoro-20261127-1640.awp
```

走的是**同一个入口、同一个解析**（`pluginpkg.preview` 与 `pluginpkg.build` 共用
`code_files` / `data_files`），只是不回字节。所以预览里数出来的东西与真的装进去的东西
不可能不一致 —— 这一点比省一次读更重要。

文件本身走 HTTP 下载：同源 + `content-disposition: attachment`，浏览器与 WebView2 都会
把它当成一次下载，而不是把 zip 当一页打开。文件名是 `<pid>-<年月日-时分>.awp`（纯 ASCII，
中文标题在包的 `awp.json` 里，不在文件名里）。

---

## 5. 导入：两步，且不替人做主

1. 选文件（`.awp`）→ 服务端**只看不写**（`dry=1`）→ 面板显示：

   ```
   番茄钟（pomodoro）· 12 个文件 / 8 KB（含数据）· 已经有同名程序，换个名字
   ```

2. 确认「装成哪个程序」（`导入为`，撞名时预填一个空着的建议名）→ 点「导入」。

两条边界：

* **不覆盖**：撞名就拒。一个已有程序的数据不该因为一次手滑而消失。
* **不改名**：撞名时只**建议**（`pomodoro_2`），改不改由人在「导入为」里定。
  换了名字，`pid`（目录名、能力名前缀）就变了，所以这件事必须让人看见。

---

## 6. 拒绝清单（每一条都是「宁可装不上，也别装上一个半成品」）

| 判据 | 被拒之后会发生什么 |
|---|---|
| zip slip（`plugin/../../x`）、绝对路径、盘符、重名条目 | 解包**之前**就拒 —— 等写完再判，越界的文件已经在包外了 |
| 单文件 > 32 MB / 解包总量 > 64 MB / 压缩比 > 120 倍（>1MB 才看） | 拒（头里可能是别人写的尺寸，真字节读完再核一次） |
| 缺 `plugin/plugin.json` 或 `plugin/backend.py` | 拒：「这个包不完整」 |
| `awp.json` 说没带数据，包里却有 `data/` | 拒：**包在说谎**，说谎的包不该被信任 |
| 格式号不是 1 | 拒（未来格式不静默读成这一版） |
| `pid` 不合 `^[a-z][a-z0-9_]{0,31}$` / 是保留名（`assistant` / `dev`） | 拒，与装载处同一句理由 |
| 已经有同名目录 | 拒（不覆盖、不改名） |
| 装上了但**起不来** | **整份回滚**：静态校验（`kernel.check_plugin`）+ 子进程 import 探针（`toolbox._import_probe`） |

最后一条是重点：它与「agent 写程序」**同一道门**。语法没错但一 import 就炸的程序，
装上去的结果是「开机少一个程序」，而那时旁边没人能救 —— 所以导入也跑那一次探针，
不过就把这次新建的目录整份删掉。

---

## 7. 代码入口

| 地方 | 是什么 |
|---|---|
| `agentworkspace/pluginpkg.py` | `build` / `read` / `preview` / `install` / `free_pid` —— 纯逻辑，不含 HTTP |
| `GET /api/plugins/export?pid=…[&data=1][&dry=1]` | `dry=1` 回 JSON；否则回 zip + 下载头 |
| `POST /api/plugins/import?name=…[&dry=1][&as=pid]` | **body 是包的原始字节**（不是 JSON）；`_origin_ok()` 照旧在最前面 |
| `state.programs[].builtin` | 内置程序（小助理）`True`、插件 `False`：面板靠这一格挑清单，不硬编码 id |

**这条路只属于人**：没有对应的 agent 工具。原因不是权限 —— agent 本來就能 `plugin_write`
写任意程序 —— 而是**它没有「挑一个本地文件」这条路**：包是人在磁盘上选的，
而「这个文件从哪来」只有人答得上。

---

## 8. 已知没做

* **不签名、不校验来源**：本机单用户，包里的 `backend.py` 会被执行。装着别人的包
  与装着一个别人给的 Python 脚本是同等级的事（`docs/plugin-mechanism.md` 里那条
  「本机单用户」边界照旧）。
* **不联网安装**（没有 URL 导入 / 没有「从市场装一个」）：那会引入来源与版本两件事，
  而这两件事现在都不存在。
* **WebView2 那条下载路径没验到**：这台开发机在 session 0（无交互桌面），
  `CreateCoreWebView2ControllerAsync` 直接 `E_ABORT`。真浏览器（Playwright + 真 Chrome +
  真服务器）那条验过：点「导出」抓到真文件、解开核对条目；选一个真文件「导入」也验过。
  桌面壳里的保存对话框长什么样，得在一台有桌面的机器上看。
