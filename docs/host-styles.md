# 宿主样式 → 插件：借，不是抄

> 一句话：插件的样式不该是「抄宿主的」，而是「引宿主的」。
> 那个 URL 是 `/aw.css` —— **宿主自己引的也是它**，不是它的副本。
>
> 而且：**宿主不会替你注入。** 引了就有，不引就是系统默认。这是刻意的，见 §2。

## 0. 起点：这件事不是"风格统一"，是"继承根本不存在"

插件页住在 `<iframe src="/plugin/<pid>/">` 里。同源，但是**另一份文档**。
三条都断在文档边界上：

| 想传的东西 | 为什么传不过去 |
|---|---|
| `--bg`、`--accent` 这些自定义属性 | 它们沿**元素树**继承。iframe 里的 `<html>` 不在宿主的元素树里 |
| `::-webkit-scrollbar{…}` | 文档级伪元素，只作用于它自己那份文档 |
| `color-scheme` | 每个文档各算各的（原生输入框、滚动条底色、下拉箭头都看它） |

第十轮把宿主的滚动条从头做了一遍（17px → 10px 热区 / 4px 视觉、箭头归零、
两档对比度按 WCAG 算过）。那时候宿主自己好看了，**插件页里还是那条 17px 的系统默认条** ——
两张截图放在一起像两个产品。原因不是"忘了改插件"，是上面那三条：
**你在宿主页写下的样式，一个字节都不会进 iframe。**

于是「让插件像宿主」只有两条路：

- 每份插件各抄一遍 —— 第一处改动起开始漂移，而且抄的人（包括 agent）不会记得回来改；
- 或者，**同一个 URL**。

这份文件就是那个 URL。

## 1. 两种用法，一份文件

| 用法 | 写什么 | 拿到的 |
|---|---|---|
| **① 只借样式** | `<link rel="stylesheet" href="/aw.css">` | 令牌 + 底座 + 滚动条；深浅跟着**系统**走（`@media` 兜底） |
| **② 借样式 + 借桥**（推荐） | 上面那行 + `<script src="/aw.js"></script>` | 同上，深浅跟着**宿主设置的那一档**走 |

`/aw.css` 与 `/aw.js` 都由宿主现发（`server.py` 的两条路由），字节与包里的文件逐字相同。
selftest 有一条断言在比对它们 —— 如果哪天变成"另一份精简版"，两份迟早不一致，
而"不一致"的表现形式是某个页面在某一档主题下颜色不对，最难查的那类 bug。

## 2. 为什么不注入（这一节是给下一个想加回来的人看的）

发布前这里曾有过第三种用法：宿主在 iframe 的 `load` 时把 `/aw.css` 插进去、顺手把
`data-theme` 贴过去，**插件零协商**。它被撤掉了，理由不是技术上的：

1. **悄悄改别人的文档，作者不知道自己的页面被改了。** `box-sizing` 从 `content-box`
   变成 `border-box` 这件事，界面上完全看不出来，只在某个宽高算错的时候露头。
2. **它把「这个插件没有借宿主样式」这个事实藏起来了。** 页面看着一切正常，作者就
   永远学不会，插件也永远停在下限（滚动条），到不了上限（用宿主的视觉语言画自己的控件）。
3. **它让契约变得不必要。** 既然宿主会注入，为什么还要写 `link`？没人写，就没人读。

这与第 47 轮那条原则是同一条：**系统替你把偏差藏起来，比报错更坏。**

所以现在是：宿主一个字节都不碰插件文档。它只出三样东西 —— 那个 URL、那座桥、
以及**说出来**：开发者模式下 `dev_style_guide()` 给一份能直接粘的骨架，
`dev_page_check()` 的报告里有一行 `◇ 样式`（引没引、几个裸 hex）。那一行**不判错**：
没借不是坏页面，只是没借。

## 3. `@layer` 是这份文件的骨架，不是风格

整份 `aw.css` 被两个层包住：

```css
@layer aw.tokens, aw.base;
```

作用只有一个：**引进来那份不会反客为主**。CSS 里未分层的规则永远赢过分层的规则，
与书写顺序无关。所以：

- 插件自己写了 `body{background:#fff}` → 它赢，`aw.base` 不会盖掉它；
- 插件没写滚动条 → `aw.base` 里的伪元素生效，滚动条自动变成宿主那条；
- 插件想退出某一层，写一条**未分层**的同名规则即可。那是退出口，不是漏洞。

支持区间：`@layer` 需要 Chromium 99+ / Gecko 97+。桌面壳走 WebView2，满足。

## 4. 契约：只认 `--aw-*`

```
--aw-bg      --aw-panel   --aw-line    --aw-ink     --aw-dim
--aw-bubble  --aw-accent  --aw-ok      --aw-bad
--aw-sb      --aw-sb-thumb            --aw-sb-thumb-hi
```

四条规则：

1. **插件只用 `--aw-*`。** 宿主内部还叫 `--bg` / `--panel` / …，那是它自己的别名
   （`index.html` 的 `:root` 里一行行映射过去）。那不是契约，随时会变。
2. **插件可以加自己的语义变量**，但值必须来自上表：`--card: var(--aw-panel)`。
   这是 helloworld 现在的写法（它以前抄了六个颜色值，宿主改一次色它就停在旧色上）。
3. **插件不写裸 hex。** 写了就等于抄了一份 —— `dev_page_check` 的 `◇ 样式` 那行会数出来。
4. **插件不写 `::-webkit-scrollbar`、不写 `color-scheme`。** 写了就赢过 `aw.base`
   （未分层 > 分层），然后它就得自己维护 WCAG 对比度那两档 —— 那是宿主该管的事。

这份清单**只存于 `aw.css`**。`dev_style_guide()` 里的那一份是**现读**的（`_aw_tokens()`
用正则从 CSS 抽），所以不会漂移 —— 与 `dev_host_services()` 从活代码反射是同一条判据。

## 5. 深浅是怎么跳过去的

```
config.json（真源：auto / dark / light）
   └─ /api/state.settings.theme → 宿主 applyTheme()
        ├─ ① 宿主自己的 <html data-theme>            ← aw.css 的 :root[data-theme=light] 认它
        ├─ ② 事件 ui.theme（EventSource）
        │     ├─ aw.js：paint() → 插件自己那份文档的 <html data-theme>
        │     └─ 原生窗口：/api/theme 一问一答
        └─ ③ （撤掉了）宿主贴给 iframe —— 现在没人替插件写这个属性
```

为什么不让插件各自 `paint()`：抄的人一多，总有一份忘了跟着改 —— 与抄颜色是同一个病。
`aw.js` 现在自己会做这件事（`function paint()`）。所以**引了桥就什么都不用做**；
只引样式不引桥的页面，深浅跟随系统。

`@media (prefers-color-scheme:light)` 那一段是兜底，只服务「引了样式、没引桥」的页面。
它的门是 `:root:not([data-theme])` —— 属性一出现它立刻失效，**两条判据永远不可能同时
说话**。第十轮踩过的坑正是这个：宿主页里留着 `@media`，设置里又选深色，于是
"设成深色的人被系统切浅"。

那段浅色与主浅色块必须**逐字相同**；selftest 有一条断言在比对它们的声明集合
（同一份浅色写两遍，那正是要漂移的地方）。

## 6. 自建插件怎么落地（给 agent 的操作顺序）

1. **先调 `dev_style_guide()`** —— 骨架、令牌（现读的）、四条纪律，一份就够；
2. `<link rel="stylesheet" href="/aw.css">` 放 `<head>` 里、自己的 `<style>` **之前**；
3. `<script src="/aw.js"></script>`；
4. 颜色一律 `var(--aw-*)`，不写裸 hex；
5. 不写滚动条样式、不写 `color-scheme`；
6. 动手前先 `dev_host_services()` —— 清单从活代码反射，三面（backend / web / native）同名；
7. 写完 `dev_page_open` + `dev_page_check(shot=true)` 看**真页面**：报告里 `◇ 样式`
   那行会说清引没引；`areas="style"` 可以单跑这一面。

## 7. 已知没做的（边界，不装作做了）

- **没有强制、也没有自动兜底**：插件不引 `aw.css` 就拿到系统默认（17px 滚动条、浏览器
  给的字体与底色）。宿主不拦、不补、不提示到界面上 —— 只在开发者模式的自查报告里
  写成一行事实。这是这一轮**故意**选的：能强制的地方，就没人会去读文档。
- **没有控件库**：`aw.css` 只有令牌 + 底座（正文、滚动条、盒子模型），
  没有任何 `.btn` / `.card` 之类的组件类。现在宿主自己的按钮是 index.html 里
  的页面私有 CSS —— 要变成公共组件，得先把它们从宿主页里抽出来，
  那是另一件事（也是这套机制的下一步）。
- **没有 lint 门**：`◇ 样式` 只报事实，不阻断。它数得也粗（声明值里的 3/4/6/8 位 hex，
  `url(#grad)` 会被算进去）—— 目的是"让偏差可见"，不是"判它错"。

## 8. 验收凭据

- `agentworkspace/web/aw.css` 是唯一真源；`GET /aw.css` 读的就是它（`server.py:158`）。
- `index.html` 只留 `:root` 别名 + 窄栏那条 `#rail::-webkit-scrollbar{width:8px}`；
  selftest 断言「宿主页里 `::-webkit-scrollbar` 只出现 1 次」—— 多一份就红。
- selftest 断言「宿主**不**注入」：`index.html` 里不许出现 `data-aw-skin` / 往
  `contentDocument.head` 插 `link` 的代码 —— 这条门是专门挡"下次有人又觉得兜底更省事"的。
- selftest 断言 `dev_style_guide()` 里的 `--aw-*` 全部存在于 `aw.css`（防手写清单漂移）。
- selftest 断言 `◇ 样式` 的两种文案各自成立（没引 / 引了有裸 hex）。
- `plugins/helloworld/ui/index.html` 是范本：它以前抄了六个颜色，现在只有
  `--card: var(--aw-panel)` 一条本地变量，外加 `<link href="/aw.css">`。
