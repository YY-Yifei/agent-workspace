# 停止 = 撤回：上下文回退到最后一条消息

> 语义一句话：**人按停止，这一轮从「模型看到的历史」里消失；文件里的事一字不改。**
> 界面上那一条不删，缩成一枚可展开的「已停止」记号 —— 人还得知道发生过什么。

## 0 · 为什么不能删行

`sessions.py:12-19` 的三条不变量里，第一条就是 **append-only**：

> 进程被杀最多坏最后一行，读的时候跳过即可；没有读-改-写，也就不会出现「两份真相」。

而且停止是**并发**动作：人点按钮的那个线程，和正在跑的 `_one_turn` 协程，
是两条独立的线。读-改-写在这里意味着「撤回」与「记录」抢同一个文件位置 ——
那是这个仓库最贵的一类故障（两份真相、半行 JSON）。

所以：**撤回是一次追加**。文件仍然是「发生过什么」的完整记录，
「模型看到什么」是它的**投影**（`sessions.py:16` 原本就是这么设计的）。
撤回改的是投影，不是事实。

## 1 · 数据模型

### 1.1 每轮带上 turn id

`Store.append_user` / `append_agent` 各多一个 `turn: str = ""`，
落盘时写进 `{"t":"user","turn":"…"}`。值取 `turn.turn_id`（aaas 给的）——
`_record_user` 调用点在 `link.py:675`，那时 `caller.send` 已经返回，id 手上就有。

老记录没有 `turn` 字段 → **永远不可撤回**。这正确：历史里的事早就定了。

### 1.2 撤回记录

```json
{"t":"retract","turn":"<turn_id>","ts":…,"why":"user-stop","tools":3}
```

追加一条，`durable=True`（与人说的话同级 —— 丢了它，重启后那两句会**复活**）。

`tools` 是这一轮里**真的执行过几次**工具调用，由 `_one_turn` 数 `functionResult`
事件中 status 为 ok 的那几条（今天的 `append_call` 无生产调用者，见 §6，
所以这个数只能从 wire 上数，不能从盘上读）。

### 1.3 投影

`Store.messages()` 多一个参数 `include_retracted: bool = True`，返回的每条多两个键：

| 键 | 含义 |
|---|---|
| `turn` | 属于哪一轮（可能为空 = 老记录） |
| `retracted` | 这一轮被撤回了 |

分组靠 `turn`：同一 `turn` 的 user + agent + call 行，一起撤、一起画。
**一个判据（`retracted` 布尔）贯穿全部四个消费者**，不再有第二份「这条算不算被撤回」：
`history()`（模型）· `messages()`（界面）· `stats()`（计数）· `_ctx()`（连接层）。

## 2 · 什么时候撤回：唯一一条判据

```
final.status == "cancelled"  且  turn.turn_id ∈ self._stop_asked
```

两条都要满足，理由：

- **必须是 cancelled**。若这一轮在取消生效前**已经跑完**（status `completed`），
  答案是真的 —— 撤回它等于删掉一份真产出，而且人按停止的意图是「别跑了」，
  不是「把你说的收回去」。这种情况下什么都不撤，答案留着，人想重来就再说一遍。
- **必须是我们请求过停止的那一轮**。服务端也可能自己取消（超时 / 上游关闭），
  那不是人的意志，不该替人做撤回这个决定。

`cancel()` 受理成功时记 `self._stop_asked.add(turn_id)` —— 一个 set，
`cancel` 与 `_one_turn` 分别在不同线程，set 的 add/`in` 在 GIL 下是原子的，
不需要额外锁（也**不能**在这里拿 `_send_lock`，见 `link.py:614-618` 那条教训）。

**判据落在终态，不落在点击那一刻。** 点击只是「请求」（`link.py:717` 的文档说得很清楚），
终态才决定这一轮算不算数。于是界面不会出现「点了停止就有东西消失，可它其实还在跑」；
界面在终态时**一次性**从「正文」切到「记号」，中间没有半态。

## 3 · 撤回发生在哪一行代码

`_one_turn` 的尾巴（`link.py:700-714`）变成：

```
final = await turn.end()
self._record_agent(turn.turn_id, text_out)          # 照旧写：事实不删
self.store.append_usage(...)                        # 照旧：账单不撤
if final.status == "cancelled" and turn.turn_id in self._stop_asked:
    self.store.retract(self.pid, self.sid, turn.turn_id, tools=n_ok)
    self._load(self.sid)                            # 整份替换（link.py:896 的既定做法）
    self._emit("turn.retracted", {...}, source="agent")
```

**写是谁负责的，撤回也由谁负责**：只有一个写入者（这一轮的协程），
所以没有竞态、不需要跨线程锁、重复调用天然幂等（第二次读到已有 retract 就跳过）。

## 4 · 撤回之后，各处的事实

| 消费者 | 变化 | 依据 |
|---|---|---|
| `_ctx()`（模型） | 跳过 `retracted` 的条目 → **上下文恰好等于上一条消息** | `link.py:827` |
| `history()` | 同上（它本来就会跳过空文本） | `sessions.py:269` |
| `stats().turns` | 只数未被撤回的 user 行 | `sessions.py:292` |
| 标题 | 若当前标题是**自动**生成的、且出自被撤回的那句 → 用新的首句重取 | `sessions.py:187` |
| `usage` / token | **不撤**。撤回的是上下文，不是账单 | `sessions.py:294` |
| 界面重载 | 记号由盘上的 `retract` 行驱动，刷新不复活、也不消失 | `server.py:253` |
| 别的窗口 | SSE `turn.retracted` → 就地撤掉那条气泡 | `link.py:378` |

**标题需要一处小加固**：`title_once` 走 `rename()`，写出的 meta 分不清「人改的」
与「自动取的」。加一个 `auto: True` 字段，`rename()` 由人调用时不带 —— 
于是「只在自动标题上重取」这条判据是白纸黑字的，不是靠字面比较猜的。

## 5 · 界面：最后一条的「特殊效果」

### 5.1 形态

被撤回的一轮**塌成一条**：

```
┌ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┐
┊ ↺ 已停止 · 这一轮不计入上下文      [展开] [重新发送] ┊
┊   「把那个配置改一下」                                ┊
└ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┘
```

- 虚线边、低饱和、比正文小一号 —— 一眼看出它**不是对话的一部分**；
- 原话**留着**（截断成一行）：不知道刚才问了什么，就没法重发；
- 半句回答与工具卡收在「展开」后面，展开后正文加删除线、工具卡标「已中断」；
- 「重新发送」把原话填回输入框（`link.py` 不需要新接口，就是一次普通 `send`）。

### 5.2 为什么不画成「消失」

`index.html:1353` 那条注释是对的：*「已经产出的内容保留，删掉等于撒谎」*。
但结论要往前走一步 —— **「保留在正文里」和「保留着」不是一回事**。
把它降级成记号，既没有抹掉事实，也没有让一段不算数的话继续占着正文的位置。
两者都占？不：**正文归人，记号归历史**。

### 5.3 眼下那几处要改的点

| 位置 | 现在 | 改成 |
|---|---|---|
| `turn.started`（1589） | 只清 `S.cur` | 顺手把 `d.turnId` 记到气泡上（撤回时按 id 找，不靠「最后一个」） |
| `turn.retracted` | 不存在 | 找到那条 → 收成记号；流式还在跑时**不画**（等终态） |
| `markStopped`（1356） | 写 `m.stopped=true` + 注脚 | 删除（整条被记号取代）；`dropEmpty` 同理 |
| `msgHtml`（1450） | `.stopnote` | 换成 `.retract` 记号块 |
| 重载映射（497 / 784 / 1734） | `h.text \|\| ''` 直译 | 按 `turn` 分组：整组 `retracted` → 一枚记号 |
| `.stopnote` 样式（300） | — | 新增 `.retract`：虚线 + `--dim` + hover 才亮 |

动效：终态到达时 180ms 收起（`transform: scaleY(1→0)` + 淡出），记号淡入；
`@media (prefers-reduced-motion)` 里直接换、不播。

## 6 · 一处必须说清的代价：世界没回退

撤回的是**上下文**，不是**世界**。那一轮里 `plugin_write` 改过的文件、
跑过的 shell，都还在。而撤回之后，模型**看不见自己做过这些**。

这是这套语义唯一一处会伤人的地方，三个选项：

| 选项 | 做法 | 评价 |
|---|---|---|
| **A 完全不留痕** | 上下文严格等于上一条消息 | 字面满足需求，但模型会把同一件事**再做一遍**（写文件 → 重写） |
| **B 一次性提示**（推荐） | 仅当 `tools > 0`：下一轮的 `instructions` 末尾追加一行，用完即弃、不入历史 | 不伪造任何发言、不污染对话，且只在真危险的场景出现 |
| C 投影里留一行 | 折进 history | 只能塞成 user/agent，两条都是**假发言**（`link.py:650` 那条注释反对的正是这个） |

B 的具体一行：

```
[宿主] 上一轮被用户停止并已撤回；期间已执行过 3 次工具调用（结果与参数都不在上文）。
若新请求涉及同一件事，先查当前状态，不要假设文件还是原样。
```

`tools == 0` 时**一个字都不加** —— 没执行过东西的撤回是干净的，
再补一句就是把噪音当成提醒。

## 7 · 并发、幂等、以及三种「没停成」

| 情形 | 行为 |
|---|---|
| 点了停止，但这一轮已 `completed` | 不撤回；答案留着（§2） |
| `cancel` 回 `error`（没送出去） | 不记 `_stop_asked` → 不撤回；界面照旧「它可能还在跑」 |
| `cancel` 回 `idle` | 没有轮次可撤 → 不撤回 |
| 15 秒 `stopTimeout` 后终态才到 `cancelled` | 照常撤回（判据在终态，与界面解锁时机无关） |
| 重复的 retract 记录 | `retract()` 先读后判：已有就返回 `False`，不追加第二条 |
| 撤回后立刻 re-send | 新的一轮，`base = _ctx()` 已是干净的那份 → **不会出现两条连续 user** |

## 8 · 门（先红后绿；一条门只回答一个问题）

| # | 门 | 现状 | 断言 |
|---|---|---|---|
| 1 | 撤回门 | **红** | 取消一轮（零 delta）→ 下一轮 `_ctx` 里没有那句 user，也没有空 agent |
| 2 | 半句门 | **红** | 取消一轮（吐了半句）→ `_ctx` 不含那半句 |
| 3 | 不重复门 | **红** | 取消 → 重发同文 → `_ctx` 里该文本**只出现一次** |
| 4 | 重载门 | **红** | 撤回后**新开一个 Store** 重新投影 → 仍不含那两句（防「重启后复活」） |
| 5 | 计数门 | **红** | `stats().turns` 不把撤回的一轮算进去；标题不残留被撤回的首句 |
| 6 | 界面门 | **红** | e2e：撤回后 DOM 里 `.retract` 恰好一枚、原气泡不在；点「重新发送」→ 输入框 = 原话 |
| 7 | 不撒谎门（护栏） | 绿 | `completed` 后按停止 → **没有** retract 行，答案仍在 `_ctx` 里 |
| 8 | 幂等门（护栏） | 绿 | 连按三次停止 → 盘上 `t=="retract"` 恰好一条 |
| 9 | 副作用门（护栏） | 绿 | 撤回的一轮执行过 2 次工具 → 下一轮 instructions 含那一行；执行 0 次 → **不含** |
| 10 | 变异验证 | — | 把 `_ctx` 的过滤删掉 → 门 1/2/3 必须变红（防假绿） |

门 7/8/9 是**护栏**：它们现在就绿，作用是「新代码不许把关闭的东西弄坏」。
护栏门同样要写，因为这次改动动的正是「什么算发生过」这件事。

## 9 · 落地顺序

1. **存储**：`append_user/append_agent` 加 `turn`；`retract()`；`messages(include_retracted)`；
   `history()`/`stats()` 过滤；`title_once` 的 `auto` 标记。→ 门 4/5
2. **连接层**：`_stop_asked`、`_record_*` 传 turn id、终态判据、`turn.retracted` 事件、
   `turn.completed` 补 `turnId`。→ 门 1/2/3/7/8
3. **接口**：`/api/p/<pid>/session/<sid>` 的 rows 带 `turn`/`retracted`（纯附加字段）。
4. **界面**：分组记号、动效、重新发送。→ 门 6
5. **那行提示**：`instructions()` 里消费一次性 `_retract_note`。→ 门 9

## 11 · 实施时改了两处（与上面的设计不同，理由在此）

### 11.1 不另发 `turn.retracted` 事件：由 `turn.completed` 带 `retracted`

原设计（§3）说终态到了再发一条 `turn.retracted`。实施时并进了 `turn.completed`：

```json
{"status":"cancelled","turnId":"…","retracted":true,"text":"…"}
```

理由：**同一件事只该有一个事件**。分两条意味着界面要依赖它们的**顺序**——
先收到 completed 就画正文、再收到 retracted 就塌掉，中间那一帧是「答案出现了
又消失」。这正是这个仓库最反感的一类竞态（两份真相、半行 JSON、看着对其实错）。
并进一条之后，界面在一个帧里决定画什么，没有半态。

代价说清楚：`turn.completed` 多了一个字段，读它的地方要知道这个字段存在。
所以判据只写在一处（`_retract_if_stopped`），界面只读不判。

### 11.2 首句被撤回 → 标题退回 `新会话`，而不是留着一个不存在的题目

`retitle_auto()` 在「一句话都不剩」时把自动标题退回默认值。留着旧名字会让人在
会话列表里看见一个**这个会话里已经不存在的问题**；而 `title_once()` 本来就认
`DEFAULT_TITLE` 这个值，所以退回默认之后，下一句话会重新取名 —— 两条路径同一个
口径。

人改过的名字一个字都不动：判据是 meta 里的 `auto` 标记，不是字面比较。

## 10 · 不做

- 不做读-改-写、不删行（§0 的不变量）。
- 不撤 token 账单（真的花了）。
- 不改 `sys=True` 接力消息的语义（它们照样可撤，因为也带 turn id）。
- 不为「人按了停止但没停成」造第四种状态（`cancel` 的三值已经够用，见 `link.py:728`）。
